## 一、scp_codes 的标准定义（PTB-XL）

在 PTB-XL 数据集中：

> scp_codes = SCP-ECG diagnostic / statement codes

也就是
SCP-ECG（Standard Communications Protocol for Computer-assisted Electrocardiography）定义的一组心电图诊断或描述性编码。

它表示：
某一条 ECG 记录被自动或人工标注的诊断陈述（diagnostic statements）及其置信度/权重。

---

## 二、数据结构层面的含义

在 PTB-XL 的 ptbxl_database.csv 中：

scp_codes


这一列通常是一个 JSON / dict 风格的字符串，例如：

{
  "NORM": 100,
  "SR": 80
}


含义是：

| Code | 含义 | 数值 |
|----|----|----|
| NORM | Normal ECG | 100 |
| SR | Sinus Rhythm | 80 |

其中：
- key：SCP-ECG code
- value：该诊断 statement 的置信度或重要性权重（0–100）

---

## 三、SCP-ECG code 本身是什么？

SCP-ECG 是一个 国际标准（IEC 61967 / EN 1064），用于：
- 心电图设备之间的标准化通信
- ECG 诊断结论的结构化表达

这些 code 本质上是：
- 高层诊断 / 形态学 / 节律 / 轴偏移 / 传导异常等 statement
- 不是 SNOMED / ICD / UMLS 直接编码

例如：

| Code | 描述 |
|----|----|
| AFIB | Atrial Fibrillation |
| RBBB | Right Bundle Branch Block |
| LBBB | Left Bundle Branch Block |
| LVH | Left Ventricular Hypertrophy |
| IMI | Inferior Myocardial Infarction |
| RAE | Right Atrial Enlargement |

## 一、UMLS 的“词表”是什么概念

在 UMLS 中，所谓“词表”指的是 Source Vocabulary / Source Terminology，例如：

- SNOMED CT
- ICD-10 / ICD-9-CM
- LOINC
- MeSH
- RxNorm

每一个 source 在 UMLS 里都有：
- 明确的 SAB（Source Abbreviation）
- 成体系的 code → term → CUI 映射

SCP-ECG / scp_codes 并不满足这一条件。

---

## 二、SCP-ECG / scp_codes 在 UMLS 中的真实状态

### 1️⃣ 不存在独立的 SCP-ECG 词表

在 UMLS 的：
- MRCONSO
- MRSAB

中：
- ❌ 找不到 SCP / SCP-ECG / 12SL 作为 SAB
- ❌ 没有完整的 code system 被整体收录

因此：
> UMLS 并未系统性收录 SCP-ECG 作为一个 source vocabulary。

---

### 2️⃣ 但“概念级内容”可能被其他词表覆盖

这是容易误解的地方。

很多 scp_codes 所表达的 临床概念本身，确实存在于 UMLS 中，例如：

| SCP-ECG statement | 是否能在 UMLS 找到 | 来源 |
|----|----|----|
| Atrial fibrillation | ✅ | SNOMED / ICD |
| Right bundle branch block | ✅ | SNOMED |
| Left ventricular hypertrophy | ✅ | SNOMED |
| Sinus rhythm | ✅ | SNOMED |
| Undetermined rhythm | ⚠️（语义不稳定） | 无标准诊断项 |
| Retrograde conduction | ❌ / ⚠️ | 偏机制描述 |

注意：
存在的是“概念”，不是 SCP 的 code。

## 二、为什么 UMLS 里不会有 scp_codes

### 1️⃣ UMLS 的定位

UMLS 的核心目标是：

> 整合“医学本体 / 受控术语”
而不是
> 整合“医疗设备输出标准”

SCP-ECG / 12SL 本质上是：
- 心电图设备的 诊断输出标准
- 面向 机器通信与报告
- 不等同于医学知识本体

因此：

| 标准 | 是否属于 UMLS 范畴 |
|----|----|
| SNOMED CT | 是 |
| ICD | 是 |
| LOINC | 是 |
| MeSH | 是 |
| SCP-ECG | 否 |
| GE 12SL | 否 |

---

### 2️⃣ 技术实现层面（SAB 角度）

在 UMLS 的 MRCONSO.RRF 中：
- 每一个概念都来自一个 Source Abbreviation（SAB）
- 你找不到类似：

SAB = SCP
SAB = SCP_ECG
SAB = 12SL


因此你不可能通过：

WHERE SAB = 'SCP'


查到任何条目。

- SAB 仍然是 SNOMEDCT_US

### 2️⃣ 被吸收到 UMLS 的“心电图表现”

例如：
- *Right axis deviation*
- *Left bundle branch block*

这些是：
- ECG finding
- 被 SNOMED / MeSH 正式收录
- 与 SCP 中的部分 statement 语义重合

## 一、PTB-XL 特征类型

PTB-XL 提供两类常用特征：

1. 原始信号特征 / 波形指标（Signal Features）
- 例如：
P_Area_I, P_Duration_II, QRS_Amplitude_V3

- 本质是 ECG 波形参数，计算自 12 导联 ECG 信号
- 用于 ML 模型训练
- 类型：连续数值（float）

2. 诊断 / 标签特征（Label / SCP codes）
- 例如：
scp_codes → AFIB, RBBB, NORM ...

- 本质是 诊断语义，可尝试映射到 SNOMED / UMLS CUI

---

## 二、为什么特征 "P_Area_I" 不能映射

### 1️⃣ 它是物理量/测量值
- "P_Area_I" = P 波面积在导联 I 上
- "QRS_Duration_V2" = QRS 波时长在 V2 上
- 这些是 信号工程特征，不是医学概念
- UMLS 收录的是概念 / 诊断 / 表现 / 药物 / 检查类型，而不是原始数值指标

### 2️⃣ 对应的概念在 UMLS 里不存在
- UMLS 有 LOINC 对应一些 lab test / ECG test 的整体概念，但：
- 并没有单独到 导联 + 波形指标 级别的术语
- 例如 "P wave area in lead I" 并不是标准概念

### 3️⃣ PTB-XL 数据集官方也没有提供映射
- PTB-XL 官方文档：
> "Signal features are for ML use and are not mapped to medical ontologies."
- SCP codes 才有尝试映射到 SNOMED / UMLS

---

## 三、总结规则

| 特征类型 | 能否映射到 UMLS | 说明 |
|----|----|----|
| 原始 ECG 波形指标（如 P_Area_I, QRS_Duration_V3） | 否 | 属于信号数值特征，没有标准概念 |
| SCP / 12SL 诊断 codes（如 AFIB, LVH） | 部分可映射 | 映射是基于语义对齐，而非原始 code |

---

## 四、对你 KG / ML 工作的影响

1. 信号特征不用映射 UMLS
- "P_Area_I"、"QRS_Duration_II" 等直接作为 ML 特征
- 可加一个“测量指标属性”节点，如果要在 KG 中记录波形指标也可以，但不需要 CUI

2. SCP code / label 才做本体映射
- 如 AFIB → SNOMED → CUI
- 这样 KG 中既有诊断标签，又有原始波形特征
