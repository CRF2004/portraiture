整体看，Methods 现在的组织结构比之前清楚很多，主线是成立的：先讲 audit 总体框架，再讲数据集、疾病面板、扰动设计、指标分层、模型、统计分析。这个顺序基本符合读者理解路径：你要审计什么 → 用什么数据 → 审计哪些疾病/通路 → 怎么扰动 → 怎么判定 → 用哪些模型验证 → 怎么统计。fileciteturn0file0

但我觉得还有几个结构性问题，会影响审稿人阅读。

## 1. 最大问题：Methods 里“主方法”和“实验实现细节”有点混在一起

现在 III-A 到 III-E 是方法核心，III-F、III-G 是实验设置和统计分析。这个本身没问题，但 III-D “Perturbation Design” 里面承担了太多任务：

它同时讲了：

- perturbation taxonomy；
- operator 选择；
- local window；
- global transform；
- SBRAD hybrid；
- AFIB dual-class；
- sample size；
- bootstrap。

这会让读者觉得 Methods 的重心有点散。尤其是 SBRAD 和 AFIB 的特殊处理比较多，容易打断“统一 audit protocol”的感觉。

我建议把 III-D 拆得更有层次：

D. Perturbation Design and Operators
先只讲共性：local window、global transform、linear interpolation、matched controls、operator selection rationale。

然后新增一个小节：

E. Disease-Specific Perturbation Instantiation
专门讲 1AVB / BBB / SBRAD / AFIB 各自怎么落地。这样 Table II 也更自然。

现在的 III-E “Audit Metrics and Evidence Tiers” 可以顺延为 III-F。

## 2. III-B 数据集部分写得扎实，但“label circularity risk”放在这里有点突兀

你在 III-B 里写 CODE-15% 的自动标签可能导致模型学习自动标注逻辑，而 PTB-XL cardiologist-validated 作为 external credibility buffer。这个观点很重要，但放在 dataset description 里面会让 Methods 像 Discussion。

更好的处理方式是：

在 III-B 保留一句简洁说明：

> Because CODE-15% labels are automatically derived, all internal findings are interpreted as model behavior relative to the source label system; PTB-XL fold 10 provides the cardiologist-validated external check.

然后把现在那段比较详细的 “risk varies by disease...” 移到 Discussion 或 Limitations。否则 Methods 会显得解释性太强，不够“程序化”。

## 3. III-C 疾病面板很好，但应该更突出“预注册/预定义”的地位

III-C 现在是合理的，但我建议把它写得更像一个audit specification，而不是普通疾病介绍。

也就是说，你要强调：

> The disease panel defines the audit hypotheses before model evaluation.

因为你论文的核心不是“我们选了五个病”，而是“我们把医学知识转化为可检验的 pathway hypothesis”。

可以把 III-C 开头改成更硬一点：

> The audit panel functions as the protocol’s hypothesis layer. For each disease, we define before perturbation analysis: the expected positive pathway, matched controls, and ambiguous alternatives that should not be treated as confirmatory evidence.

这样审稿人会更容易接受你的 matched-control audit 是“方法”，不是事后解释。

## 4. Evidence tiers 放得对，但规则还可以更早“预告”

现在 III-A 里面提到了三档：Pathway-supported / Evidence-limited / Not supported，III-E 再正式定义。这个是可以的。

不过我建议在 III-A 只保留框架，不要写太多 tier 细节；III-E 里集中定义。否则读者会感觉同一件事被说了两遍。

特别是 III-A 的四阶段概述已经很长，可以压缩一点。Methods 的 Study Overview 应该像地图，不应该把后面的小节内容提前讲太满。

## 5. Statistical Analysis 放最后合理，但可以分成“audit statistics”和“classification statistics”

III-G 现在包含：

- patient-level bootstrap；
- model comparison；
- multiplicity control；
- feature-space validation。

这几类东西目标不同。建议至少在文字结构上分清楚：

G. Statistical Analysis

1. Uncertainty for pathway audit
patient-level bootstrap, ASS CI。

2. Classification-model comparison
DeLong, permutation tests, Holm correction。

3. Multiplicity control for external ASS tests
BH-FDR。

4. Feature-space validation
PTB-XL+ and PR baseline。

这样读者不会觉得统计方法堆在一起。

## 我建议的最终 Methods 大纲

我会改成这样：

III. Methods

A. Study Design and Audit Workflow
一句话讲核心问题：high AUROC ≠ pathway-specific evidence。然后四步流程，但压缩。

B. Datasets and External Validation Setting
CODE-15%、PTB-XL、split、preprocessing、frozen transfer。label circularity 简写。

C. Disease-Centered Audit Specification
五个疾病、expected pathway、matched controls、ambiguous pathway。Table I 放这里。

D. Perturbation Operators and Intervention Classes
linear interpolation 为什么是 primary；local window vs global transform；zero-masking 只作为 sensitivity/operator-disclosure。

E. Disease-Specific Perturbation Protocols
1AVB、CRBBB、CLBBB、SBRAD、AFIB 分别怎么扰动。Table II 放这里。sample size 也放这里。

F. Audit Metrics and Evidence Tiers
ASS、PSS、CDDC、KAS；三档 evidence tier。

G. Models and Representation Levels
XGBoost simple / Clinical-MVP / ResNet / SE-ResNet / Transformer。强调是 audit instantiation，不是模型创新。

H. Statistical Analysis
bootstrap、model comparison、BH-FDR、external feature-space validation。

## 总体判断

可以，但还没到最顺。
现在的结构已经能讲清楚方法，但最大的问题是：III-D 太重，III-B 有一点 discussion 化，III-G 有点统计方法堆叠。

你这篇 Methods 最需要保护的是一个清晰主线：

> We define disease-specific pathway hypotheses, perturb target and matched-control regions under a predefined operator, compute ASS, and test whether the pathway conclusion survives external transfer.

所有小节都应该服务这条线。现在已经接近了，再把“疾病特异实现”和“通用方法定义”拆开，Methods 会更像一篇方法论文，而不是一个复杂实验报告。

不过我建议你做几处结构性微调，让 Methods 更像一个“可复现协议”，而不是把概念、实验设计和解释逻辑混在一起。

我觉得最该改的是 III-A。
现在 Study Overview 里已经提前讲了四阶段流程、operator、ASS、CDDC、evidence tiers、external validation，信息密度很高。作为 overview 可以，但有点像把后面每节都浓缩讲了一遍。建议 III-A 保留“整体流程图式描述”，但减少指标和规则细节，把细节留给 III-D 和 III-E。这样读者不会在开头就被 ASS、CDDC、tier rule 压住。

III-B 放得对，但可以更早强调 internal/external 的角色差异。
CODE-15% 是训练和内部 audit，PTB-XL fold 10 是 external credibility set，这个逻辑很重要。你现在已经写了 label circularity risk，这一段很有价值，建议保留，但可以更明确地分成三个小段：Internal cohort、External cohort、Transfer/evaluation protocol。这样审稿人会更容易看到你不是简单做 dataset validation，而是在用外部数据验证 pathway conclusion。

III-C 和 III-D 的边界可以再清一点。
III-C 应该只负责回答：“为什么选这五个病？每个病对应什么临床 pathway 和 matched controls？”
III-D 再回答：“这些 pathway/control 具体怎么 perturb？”
现在 III-C 里有些 clinical anchoring 的内容已经开始解释 control 的合理性，没问题，但别太深入 operator 和 perturbation implementation，不然和 III-D 重叠。

III-D 是 Methods 的核心，结构最好再更工程化一点。
我建议改成：

1. Common perturbation setup
包括 R-peak detection、12-lead application、matched subset、bootstrap、exclusion rule。

2. Primary operator selection
线性插值为什么是 primary；zero-masking 为什么只做 sensitivity。

3. Local-window perturbations
1AVB、CRBBB、CLBBB、AFIB atrial window。

4. Global-transform perturbations
SBRAD rate normalization、AFIB RR regularization。

5. Operator-sensitivity analyses
放到最后，并明确“不用于 evidence tiering”。

这样比现在 “Perturbation Operator and Protocol → Class I → Class II” 更容易复现，也更能防止审稿人质疑 operator 是 post-hoc 选的。

III-E 很关键，但现在标题里 “Audit Metrics and Evidence Tiers” 合理，内容略显重。
建议把公式、CDDC、PSS、KAS 和 tier rules 分成更明显的小标题。尤其 evidence tier 的规则应该像 protocol checklist 一样清楚，因为这是你全文结论的“判案标准”。这里写得越机械、越预先定义，越有说服力。

III-F 模型部分放在 perturbation 和 metric 后面是可以的。
通常 Methods 会先讲 models 再讲 perturbation，但你的文章贡献是 audit protocol，不是 architecture。所以先讲 audit design，再讲 models as instantiations，是合理的。建议你在 III-F 开头明确一句：这些模型不是本文主要贡献，而是用于测试 protocol 的 representation/architecture ladder。你现在已经有这个意思，可以再压实。

III-G 统计分析放最后也对。
这里写得比较完整，patient-level bootstrap、DeLong、permutation、BH-FDR 都交代了。唯一建议是把“primary uncertainty quantification”和“secondary model comparison”区分得更强，避免审稿人觉得统计方法太多、主次不清。

我的总体判断：结构大方向没问题，但 Methods 现在偏“解释型 Methods”，可以改得更“协议型 Methods”。 也就是说，每节标题和段落都应尽量服务于复现：输入是什么、操作是什么、输出是什么、判定规则是什么。这样会更贴合你这篇文章的卖点——一个 matched-control pathway audit protocol，而不是单纯 ECG classification 实验。
