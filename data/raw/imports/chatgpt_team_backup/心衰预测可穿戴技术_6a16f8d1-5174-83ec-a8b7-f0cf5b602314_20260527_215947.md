这篇论文里建立“正常基线”的核心机器学习方法是：

**Similarity-Based Modeling，简称 SBM，相似性建模。**  
它不是常见的随机森林、SVM、神经网络那类分类器，而是一种**个体化、非参数的动态基线建模方法**。论文说云端平台用 SBM 学习多个生理变量之间“同时变化”的模式，先建立每个患者自己的动态正常模型，然后进入监测模式，用模型估计“此刻应该出现的生理值”，再和真实监测值比较。fileciteturn1file1

具体流程是：

1. **训练数据来源**：出院后前 **72 小时**的数据。作者假设患者出院后相对稳定，因此用这段时间为每个人建立个体化基线。fileciteturn1file4

2. **SBM 输入变量**：  
   使用的是每分钟层面的特征，包括：
   - 1 分钟 10% trimmed mean 的心率；
   - 呼吸频率；
   - 累积总体活动量；
   - 姿势。  
   另外，房颤、心动过速、心动过缓检测也和 SBM 一起使用。fileciteturn1file4

3. **正常基线怎么定义**：  
   SBM 学到的是这个患者在不同日常状态下，比如静坐、走路、睡眠、清醒时，各生理变量之间的动态关系。之后它会根据学到的模式生成“预期值”。如果实际心率、呼吸、活动、姿势等和预期值一致，就认为该患者仍接近自己的正常状态。fileciteturn1file1

4. **异常怎么量化**：  
   实际值和 SBM 预期值之间的差异会被合并成一个指标，叫 **MCI，multivariate change index，多变量变化指数**，范围是 −1 到 1。接近 0 表示和基线差不多；大于 0 越多，越提示生理状态变差，可能存在心衰恶化。MCI 是每分钟计算一次，之后用于生成每日平均 MCI 和临床预警。fileciteturn1file4

所以，准确地说：**他们不是用机器学习直接预测“住院/不住院”来建立正常基线，而是先用 SBM 为每个患者建立个体化动态正常模型，再用实际值偏离基线的程度，也就是 MCI，作为预警信号。**

## SBM 具体在做什么

你可以把它理解成一种**个体化的多变量异常检测模型**，不是传统意义上的“分类模型”。

它的逻辑大概是：

**第一步：用出院后前 72 小时建立个人基线。**  
作者假设患者刚出院后处于相对稳定状态，所以每个人都用自己出院后的连续数据训练模型，而不是用全人群平均值。输入包括 1 分钟层面的心率、呼吸频率、总体活动量和姿势；房颤、心动过速、心动过缓检测也一起使用。fileciteturn4file2

**第二步：学习“变量之间一起变化的模式”。**  
SBM 学的不是“心率多少算异常”这种固定阈值，而是学这个患者在不同状态下的动态组合关系。比如同一个患者在睡觉、坐着、走路、站立时，心率和呼吸率本来就会不同；SBM 会把活动量和姿势也放进去，估计“在这种活动/姿势背景下，心率和呼吸率本来应该是多少”。论文说 SBM 是通过学习系统变量被同时采样时的 tandem patterns 来建立动态基线模型，然后进入监测模式，用插值估计 expected values，再和实时监测值比较。fileciteturn3file0

**第三步：实时比较“实际值 vs 预期值”。**  
如果患者走路时心率升高，而模型认为这符合他的正常动态模式，就不算异常；如果活动量没有增加、姿势没有明显变化，但心率/呼吸率持续偏离自己的预期值，模型就认为生理状态开始不同于基线。论文特别强调，这样可以去掉日常活动造成的正常波动，留下“学习到的动态行为”和“当前真实生理行为”的差异。fileciteturn4file2

**第四步：把多变量偏差合成为 MCI。**  
这些偏差被合成为一个 **MCI，multivariate change index，多变量变化指数**，范围 −1 到 1。接近 0 表示和基线类似；大于 0 越多表示状态越可能变差；小于 0 则表示相对改善。MCI 每分钟算一次，然后转成每日平均 MCI，超过预设阈值就触发临床预警。fileciteturn4file2

简单说，SBM 建的不是“正常人模型”，而是：

> **这个患者在自己的日常活动、姿势和节律下，心率/呼吸等生理信号应该如何一起变化。**

## 医学依据是什么

医学依据主要有三层。

第一，**心衰恶化不是单一指标变化，而是全身生理状态的组合变化**。心衰加重时可能出现交感兴奋、心率变化、呼吸频率升高、活动耐量下降、睡眠/体位改变、房颤或快速心律失常等。单看体重或单看某一个阻抗指标容易漏掉早期变化。论文也提到，单纯每日体重监测没有降低心衰住院风险，胸腔阻抗监测也没有带来明确再住院风险下降，因此可能需要不止一个生理参数来及时识别失代偿。fileciteturn4file3

第二，**个体化建模有医学合理性**。心衰患者差异很大：有的人基础心率高，有的人用 β 受体阻滞剂，有的人有房颤，有的人活动能力差，有的人射血分数保留或降低。用统一阈值，比如“心率 > 100”或“呼吸频率 > 20”，会很粗糙。作者在讨论中明确说，这种个体化机器学习的优势是把多个生理数据流组合成每个人自己的模型，并把长期连续数据和个人生命体征的正常动态比较，而不是和人群标准比较，从而控制个体差异、识别真正异常。fileciteturn4file0

第三，**多传感器监测在心衰领域已有前例**。论文提到，肺动脉压力监测干预曾显示可降低再住院率；植入式设备的 MultiSENSE/HeartLogic 这类多传感器算法也能预测心衰事件。LINK-HF 的创新是把类似“多信号 + 动态异常检测”的思路放到非侵入式可穿戴贴片上。fileciteturn4file4

但要注意一点：这篇研究证明的是**预警信号和之后住院风险相关**，不是证明 SBM 捕捉到的每个偏差都一定是心衰机制本身。作者自己也承认这是观察性研究，没有正式训练/验证集划分，也还不知道把预警反馈给医生后是否真的能减少住院。fileciteturn4file0

所以最准确的评价是：**SBM 的医学依据是“心衰恶化会造成多维生理状态偏离个人稳定模式”；它的统计方法依据是“用个人基线做多变量异常检测”。这个思路合理，而且在 LINK-HF 中表现不错，但算法细节不透明，临床干预效果还需要前瞻性随机研究验证。**

## 🤖 Assistant (2026/5/27 22:08:48)

SBM（Similarity-Based Modeling，相似性建模）可以理解成一种**基于“正常历史样本库”的多变量异常检测/状态估计方法**。它的核心不是训练一个黑盒分类器，而是回答这个问题：

> 当前这个多维状态，能不能用过去“正常状态库”里的相似状态组合出来？  
> 如果组合不出来，或者组合出来的“预期值”和真实值差很多，就说明系统偏离了正常模式。

你找到的阿里云文章讲的是火电汽轮机版 SBM。它说得比较直白：SBM 是非参数建模方法，用历史正常状态向量组成状态矩阵 D，然后评估当前状态向量和 D 中所有向量的相似性，以判断系统是否正常。这个理解和 LINK-HF 论文里的用法是一致的，只是应用对象从汽轮机换成了人体生理信号。citeturn928379view0

## 1. SBM 的基本结构

假设每一分钟采集一次数据，每个时间点有多个变量：

\[
x_t = [心率, 呼吸率, 活动量, 姿势, ...]
\]

训练阶段先收集一批“正常状态”的历史向量：

\[
D = [d_1, d_2, ..., d_k]
\]

这里的 \(D\) 就是**状态矩阵 / memory matrix / baseline library**。在工业场景里，D 要尽量覆盖正常运行的各种工况；Oracle 对 MSET/SBM 类方法的说明也强调，它需要足够的历史数据来覆盖系统所有正常行为模式，否则新进入一个未覆盖的正常模式时就容易误报。citeturn218685view0

## 2. 在线检测时怎么估计“应该是多少”

来了一个当前观测值：

\[
x_t
\]

SBM 会计算它和历史正常库里每个状态 \(d_i\) 的相似度：

\[
K(x_t, d_i)
\]

这个 \(K\) 可以是欧氏距离变换、核函数、归一化相似度等。不同论文和实现不完全一样。然后模型会找一组权重：

\[
w_1, w_2, ..., w_k
\]

用历史正常状态的加权组合来重构当前状态的“正常估计值”：

\[
\hat{x}_t = \sum_i w_i d_i
\]

如果当前状态真的像过去某些正常状态的组合，那么 \(\hat{x}_t\) 会很接近 \(x_t\)。如果当前状态偏离正常模式，二者差异就会变大。

这个差异叫 residual，残差：

\[
r_t = x_t - \hat{x}_t
\]

工业 MSET 文献也是这个思路：用正常运行数据建立多参数估计模型，再比较实际监测参数和模型估计值之间的残差，以判断系统状态变化。citeturn218685view1

## 3. 为什么它叫“非参数”

这里的“非参数”不是说没有参数，而是说它**不预设明确的函数形式**。比如它不会先假设：

\[
心率 = a + b \times 活动量 + c \times 姿势
\]

它更像是“记住很多正常例子”，然后用相似例子来估计当前应该长什么样。所以它和 kNN、核回归、局部加权回归有点像，但 SBM/MSET 通常更强调**多变量系统状态重构**。

## 4. 状态矩阵 D 怎么选

这一步很关键。不是把所有历史数据都塞进去就完事，因为数据太多会慢，而且冗余。通常会挑选能代表正常模式的样本。

你找到的阿里云文章列了几种常见方法：选各测点最大/最小值所在状态、几何中值、K-means 聚类、相似度最小填充等。它们本质上都是为了让 D 覆盖“正常状态空间”的边界、中间状态和典型模式。citeturn928379view0

换到 LINK-HF 这篇心衰论文里，D 就不是汽轮机工况，而是每个患者出院后前 72 小时的个人生理状态。论文使用的输入包括 1 分钟层面的心率、呼吸率、总体活动量、姿势，并结合房颤、心动过速、心动过缓检测。系统用这些数据建立每个患者自己的动态基线，然后把实际监测值和模型预期值比较，最后汇总成 MCI。fileciteturn0file0

## 5. 和 LINK-HF 里的 MCI 是什么关系

SBM 负责生成：

\[
\hat{x}_t
\]

也就是“按个人基线推断，这一分钟应该是什么状态”。

然后计算：

\[
r_t = x_t - \hat{x}_t
\]

这些多变量残差再被合成为一个指标，LINK-HF 叫：

\[
MCI = Multivariate Change Index
\]

MCI 接近 0：当前状态和个人基线差不多。  
MCI 大于 0 并持续升高：生理状态越来越偏离原来的稳定模式，可能提示心衰恶化。  
MCI 小于 0：论文解释为更偏向改善方向。

所以在 LINK-HF 里，SBM 本身不是直接输出“会不会住院”。它先输出“当前状态相对个人正常基线的偏离程度”，再用 MCI 阈值触发预警。

## 6. 医学上为什么这个思路有意义

这个方法的医学合理性在于：心衰恶化通常不是单一指标突然越过某个固定阈值，而是多个生理系统一起发生变化。

比如患者可能出现：

心率相对自己的基线升高，呼吸率升高，活动量下降，睡眠/姿势模式改变，房颤或快速心律失常增多。

单独看心率，可能还在“正常范围”；单独看呼吸，也可能不夸张。但把它们放在一起看，并且和这个患者自己的稳定状态比较，就可能更早发现异常。

这也是 SBM 相比固定阈值的价值：它不是问“心率有没有超过 100”，而是问：

> 在这个人的活动量、姿势、日常节律背景下，这个心率和呼吸率组合是否还像他自己的正常状态？

## 7. 但要警惕一点

SBM 很适合“异常检测”，但它不天然知道异常原因。MCI 升高可能是心衰恶化，也可能是感染、贫血、焦虑、药物变化、房颤、运动模式改变、传感器问题等。

所以它更像一个**早期风险雷达**，不是诊断器。临床上仍然需要医生结合症状、体征、体重、BNP/NT-proBNP、肾功能、用药依从性等判断。

一句话总结：

**SBM 就是用每个人/每台设备自己的正常历史数据建立“动态正常状态库”，实时用相似历史状态重构当前应有状态，再用实际值和预期值的残差来发现异常。LINK-HF 把这个工业异常检测思想迁移到了心衰可穿戴监测上，用个人化生理偏离来提前预警再住院风险。**
