这个提示：

> [Upstream returned an empty response — please retry this message.]

本质上是：

> Claude Code 向后端模型请求结果时，上游服务没有返回有效内容，连接或响应中断了。

它不是你的代码报错，而是 Claude Code ↔ 模型服务之间 的问题。

常见原因有几种：

---

## 1. 网络不稳定（最常见）

尤其是：

- 开代理/VPN
- 公司网络
- SSH远程环境
- WSL/Docker 内网络
- 中国大陆网络波动

Claude Code 会持续流式接收模型输出，只要中间断一下，就可能得到“empty response”。

### 特征

- 运行一会才报错
- 长输出更容易出问题
- retry 后有时恢复

### 解决

- 换稳定网络
- 关闭不稳定代理
- 减少同时运行的 AI 请求
- 如果是 SSH，试试本地运行

---

## 2. 上下文太大 / Token 爆了

Claude Code 很容易把：

- 整个项目
- 大文件
- 日志
- node_modules
- build 输出

一起塞进上下文。

当请求太大时，后端有时不会明确报 token limit，而是直接空响应。

### 特征

通常发生在：

- 大型仓库
- 连续对话很久后
- 分析很多文件后
- “运行一小会”后突然断

### 解决

#### 重开 session

最有效。

#### 减少上下文

比如：

claude --add-dir src


而不是整个项目。

#### 排除垃圾目录

创建 .claudeignore：

node_modules
dist
build
coverage
.next
.git


这个非常重要。

---

## 3. Claude Code 版本问题

某些版本存在 streaming bug。

### 解决

更新：

npm update -g @anthropic-ai/claude-code


或者：

npm install -g @anthropic-ai/claude-code@latest


---

## 4. Anthropic 服务端问题

有时候是 Claude 官方：

- 限流
- 服务波动
- 模型 overload

### 特征

- retry 后恢复
- 所有人同时遇到
- 不同项目都报错

可以看：

urlAnthropic Statushttps://status.anthropic.com/

---

## 5. 输出太长导致流中断

Claude Code 特别容易在：

- 生成大段代码
- 重构整个文件
- 输出超长 diff

时中断。

### 解决

主动限制输出：

比如：

不要一次输出完整文件，只给修改部分


或者：

分步骤修改


效果会明显稳定。

---

## 6. MCP / Tool 调用异常

如果你开了：

- MCP server
- filesystem tools
- browser tools
- 自定义插件

工具挂了也可能导致 upstream empty response。

### 排查

先禁用 MCP：

claude --no-mcp


看看是否恢复。

---

## 我比较建议的稳定配置

很多人这样用会稳定很多：

### .claudeignore

node_modules
dist
build
coverage
.next
.git
*.log


### 小范围上下文

不要：

claude .


而是：

claude src/


### 经常 /clear

长对话后上下文会越来越脏。

---

## 如果你是“每次都一小会就报错”

那大概率是：

1. 网络问题
2. 项目太大
3. 上下文爆炸

尤其是大型 monorepo 最容易这样。

很多人误以为是“Claude 太笨”，其实是它把整个仓库都吃进上下文后撑爆了。
