# 一、为什么会有模糊性的本质原因（为什么你在 MIMIC 里看不出“为什么做某项检查”）
1. **EHR 不是为因果问答设计的记录系统**：很多关键“决策原因”只存在于医生脑里或纸面记忆里，EHR 只记录了动作（下了检查单、做了操作、时间、结果），但不总记录“为什么”（临床怀疑、规则、床位/科室、值班医师偏好等）。这在文献里被反复指出——用 EHR 做因果发现困难且容易被未观测混杂偏倚。citeturn0search0turn0search3

2. **选择偏倚与未观测混杂（selection & unobserved confounding）**：做或不做某检查往往与患者严重度、检验可得性、科室流程或医生偏好相关，这些因子可能没有完备记录。直接把“观察到做了检查”解释为“由先前某些体征导致”的因果链，容易误判。citeturn0search3turn0search14

3. **时间与事件稀疏、异构**：不同病人在不同时间点做不同动作，事件集合不一致（有人做 ECG，有人没做）。传统时序因果模型（如 DBN、传统 Granger）对这种异构稀疏事件支持不好。

# 二、两条可行策略（优劣比较）

## A. **先做“关联/过程挖掘 + 决策森林构建”（推荐初始路径）**
- 做法：用 process mining / sequence mining / graph aggregation 来把大量病例轨迹汇总成“从症状出发的多分叉决策森林”。记录每条边的频数、条件概率、典型前置事件集合（例如统计在做 ECG 前 6 小时内最频繁出现的 5 类事件）。
- 优点：能快速把真实世界的常见路径可视化并量化；对构建决策支持和发现异常路径非常有用。Process mining 在医疗流程可视化上已有成熟研究与工具。citeturn0search7turn0search1
- 局限：这只是**相关**，不能保证“先兆事件 → 决策”是因果关系。

## B. **做因果发现 / 因果识别（针对关键决策做深挖）**

# 1️⃣ 边的概念

在你的决策森林里：

- **节点**：可以是“患者状态”或者“医生决策”  
  - 例如 `A = 头痛`（状态）、`B = 下CT`（决策）、`C = CT结果正常`（状态）  
- **边**：表示**从某个节点到下一步节点的真实转移**  
  - 例如 `A → B`（出现多少次患者头痛 → 下CT）  
  - `B → C`（下CT → CT结果正常）  

> **边的方向必须沿着患者实际序列走**，不能随意 AB、AC、AD 组合。

---

# 2️⃣ 边频次如何统计

举个例子：

假设有三条病例序列：

| 病例 | 序列                   |
|------|------------------------|
| 1    | A → B → C → D          |
| 2    | A → B → E              |
| 3    | A → F → C → D          |

- **统计 A→B**：出现了病例 1、2 → 频次 = 2  
- **统计 A→F**：出现了病例 3 → 频次 = 1  
- **统计 B→C**：出现了病例 1 → 频次 = 1  
- **统计 B→E**：出现了病例 2 → 频次 = 1  
- **统计 F→C**：出现了病例 3 → 频次 = 1  
- **统计 C→D**：出现了病例 1、3 → 频次 = 2  

⚠ 注意：

- 不统计 **非相邻节点组合**（比如 AB → AE 或 AC → AD），因为在序列 A→B→C→D 中，A→C 并不是直接转移，而是跳过 B → 这种不属于“下一步决策/状态”的边。  
- 只有直接相邻节点（`i → i+1`）才算边。  

---

# 3️⃣ 如果想统计前后窗口的关联（可选）

你可以扩展概念：

- 定义一个 **窗口长度 w**，统计 **任意距离 ≤ w 的触发频次**  
  - 比如 w=2，序列 A→B→C→D  
    - 直接边：A→B, B→C, C→D  
    - 窗口边：A→C（跨度2）、B→D（跨度2）  
- 这种方法可以挖潜在关联，但不等同因果（因为可能被中间节点 B / C 冲淡）。

> 🔹 通常初版决策森林先只统计 **直接相邻边**，简单、可解释，容易可视化。

# 3️⃣ 多对一、多对多处理方式

- **多对一**（多个状态触发一个决策）：
  - 使用**集合型键**（unordered tuple）表示前置状态集合  
  - 统计次数 → 条件概率 = 次数 / 所有出现决策的次数  
  - 例如：`(胸痛, 高血压) → ECG`，频次 20 / 所有 ECG 100 次 → 条件概率 0.2  

- **多对多**（多个状态触发多个决策）：
  - 可以扩展 tuple 表示 `(状态集合 → 决策集合)`  
  - 或者拆解成每个决策单独处理，统计每个前置状态集合到该决策的条件概率  

- **非相邻事件**：
  - 用**滑动窗口 / 时间窗口**：例如决策前 6–12 小时内的所有事件  
  - 这样可以捕捉非紧邻触发事件  

- **权重/顺序**：
  - 可以给不同事件距离决策的时间打权重（距离越近权重越高）  
  - 如果想保留顺序信息，可用 tuple 代替 set

# 1️⃣ PM4Py 的核心原理

PM4Py 是一个 **Process Mining** 框架，主要处理 **事件日志（event logs）**：

- 输入：每条病例/流程序列 = `(case_id, activity, timestamp)`  
- 核心任务：从大量序列中自动抽取**流程模型（Process Model）**，可以是：
  - Petri Net  
  - Directly-Follows Graph (DFG)  
  - Process Tree  
- 输出：流程图/树，边可以标注：
  - **频次**：多少病例中发生过这个转移  
  - **概率/支持度**：这个转移占总病例的比例  

**关键概念**：

- **节点 = 活动/事件**（你可以把它映射为“状态节点”或“决策节点”）  
- **边 = 直接转移 / 可选窗口转移**  
- 可以计算 **直接跟随（Directly-Follows）或近邻随访（k-length window）**  
- 可以处理**非严格线性序列**，也能统计多条病例中出现的模式  

---

# 2️⃣ 多对一/多对多支持情况

## 多对一

- **定义**：多个前置事件 → 一个后置事件（决策）  
- PM4Py 默认建 **Directly-Follows Graph (DFG)** 时是基于**相邻事件**，看起来像“一对一”  
- **扩展支持多对一**：
  - 使用 **窗口技术** 或 **Heuristics Miner / Inductive Miner**：
    - 给每个事件定义前置窗口（例如前 6 小时或前 N 个事件）  
    - 把窗口内的所有前置事件作为触发集合  
    - 统计所有病例中出现这个集合 → 后置事件的频次/概率  
  - 结果就是**多对一边**（多个状态指向一个决策）  

> 核心就是**把事件组合看作触发集合，而不是只考虑直接前一个事件**。

## 多对多

- 类似多对一，只是后置事件也是集合（一个状态集合可能触发多个决策）  
- PM4Py 可以通过 **“parallel/branching”** 或 **Process Tree** 表示分叉，统计所有可能的后续分支频次  

---

# 3️⃣ 非相邻事件的处理

- 默认 DFG 只统计直接相邻事件  
- 支持非相邻事件的方法：
  1. **事件窗口（sliding window / temporal threshold）**  
     - 对每个决策事件，定义一个时间窗口（如前 6 小时）  
     - 所有窗口内事件都统计为候选前置事件  
  2. **序列模式挖掘结合 PM4Py**  
     - 可以先用 PrefixSpan / SPADE 找高频序列模式，再用 PM4Py 可视化成流程树  

> 这就允许你捕捉“非相邻触发、多对一、多对多”的模式，同时还能生成决策森林可视化。

---

# 4️⃣ PM4Py 算法流程示意（针对你的场景）

1. **准备事件日志**：
   ```
   case_id | timestamp | activity
   1       | t1        | 头痛
   1       | t2        | 血压升高
   1       | t3        | ECG
   2       | t1        | 胸痛
   2       | t2        | 高血压
   2       | t3        | 超声心动图
   ```

2. **选择挖掘算法**：
   - Directly-Follows Graph：快速，统计边频次  
   - Heuristics Miner / Inductive Miner：可以处理噪声和并行分支  

3. **统计边**：
   - 直接相邻：DFG 默认  
   - 窗口 / 滑动：多对一触发集合统计  
   - 多对多：统计所有可能分叉的后续活动集合  

4. **生成可视化决策森林**：
   - 节点 = 状态/决策  
   - 边 = 转移（标注频次/概率）  
   - 支持分叉（多对一、多对多）
