**第三，Evidence tiers 的定义有点绕，而且可能被审稿人抓。**  
你现在的 Pathway-supported 定义要求 internal 和 external ASS 都 CI lower bound > 0；Evidence-limited 又包括 external CI crosses zero；Not supported 是 ASS≤0。这个思路是对的，但表述有几个风险：

建议把规则改得更硬一点：

| Tier | 建议定义 |
|---|---|
| Pathway-supported | Internal ASS > 0 且 CI lower bound > 0；External ASS > 0 且 CI lower bound > 0 |
| Evidence-limited | Internal ASS > 0 且 CI lower bound > 0，但 external ASS > 0 的 CI 跨 0 |
| Not supported | Internal ASS ≤ 0，或 external ASS ≤ 0 |

### III. METHODS

### A. Study Design and Audit Logic  
这一节只回答：**我们的方法整体在干什么。**

建议写成三句话主线：

1. 常规 discrimination metrics 不能判断模型是否用了医学上相关的 signal pathway。  
2. 所以我们提出 matched-control pathway audit：目标 pathway 的扰动效果必须超过最强 matched control。

这里保留你现在的四阶段概述，但可以压缩。现在这部分其实写得不错，问题是后面没有始终围绕它组织。

### B. Datasets and Transfer Setting  
这一节放数据集，不要混入太多解释性讨论。

内容顺序建议：

1. CODE-15%：训练 / 内部 audit 数据集

## 我建议你重点改的地方

第一，**把 operator comparison 降权**。它很重要，但它是“为什么选 linear interpolation”的支撑，不应该在 Methods 主文里抢走 audit protocol 的主线。现在读者可能会觉得你一会儿在讲 matched-control，一会儿在讲 operator artifact，焦点有点飘。

第二，**把模型部分压缩**。Methods 里模型细节过多，会让文章看起来像“我训练了很多模型”，而不是“我提出了一个 audit framework”。SE-ResNet 和 Transformer 应该明确写成 architecture sensitivity checks，而不是并列贡献。

第三，**把 AFIB 和 SBRAD 的 protocol 讲得更层次化**。因为它们不是单纯 local-window perturbation，容易让审稿人觉得方法不统一。你要主动说：local pathway 和 global pathway 对应不同 intervention class，这是设计选择，不是临时拼接。

第四，**检查 Fig. 1**。你现在 Fig. 1 页面里还有红色批注，而且图中 “Supportive evidence / Narrow support / Transfer-stressed” 这类措辞和正文的三档 evidence tier 不完全一致。这个很危险，Methods 里既然已经定义了 Pathway-supported / Evidence-limited / Not supported，图也必须完全统一。否则审稿人会觉得分类标准前后不一致。

总的来说：**Methods 不是散到不能用，但现在像“把所有方法材料都放进来了”，还不是“围绕一个审稿人能复述的 protocol 组织起来”。** 你要把它改成：先定义 audit 问题，再定义 disease pathway，再定义 perturbation，再定义判定规则，最后才是模型和统计。这样读起来会清楚很多。
