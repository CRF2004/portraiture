## 🤖 Assistant (2026/5/27 19:03:24)

这是两个问题叠在一起了：

第一行：

```powershell
wsl: 检测到 localhost 代理配置，但未镜像到 WSL。
NAT 模式下的 WSL 不支持 localhost 代理。
```

意思是：你的 Windows 里可能开了本地代理，比如 Clash、v2rayN、VPN、Fiddler，代理地址类似 `127.0.0.1:7890`。但 WSL2 默认是 **NAT 网络模式**，在这种模式下，WSL 里的 `127.0.0.1` 指的是 Linux 自己，不是 Windows，所以 WSL 没法直接使用 Windows 的 localhost 代理。微软文档也说明，WSL2 默认 NAT 模式下，从 Linux 访问 Windows 服务要用 Windows 主机 IP；只有 mirrored 网络模式下，Windows 和 WSL 才能互相用 `localhost` 访问。citeturn517462view0

后面的：

```powershell
灾难性故障
错误代码: Wsl/Service/E_UNEXPECTED
```

这才是导致 WSL 没启动起来的核心错误。常见原因是 WSL 服务异常、`.wslconfig` 网络配置不兼容、代理配置冲突，或者 WSL 版本/Windows 版本不匹配。

先按这个顺序修：

### 1. 先重启 WSL

在 **PowerShell 管理员** 里运行：

```powershell
wsl --shutdown
wsl --update
wsl --status
wsl -l -v
```

微软文档也建议修改 WSL 配置后用 `wsl --shutdown` 让配置重新生效。citeturn517462view1

然后再试：

```powershell
wsl
```

### 2. 临时关掉 Windows 代理/VPN

把 Clash、v2rayN、VPN、Fiddler 之类先退出。

然后检查 Windows 代理：

```powershell
netsh winhttp show proxy
```

如果显示有代理，先重置：

```powershell
netsh winhttp reset proxy
```

同时去：

```text
Windows 设置 → 网络和 Internet → 代理
```

把“使用代理服务器”先关掉。

### 3. 临时禁用 `.wslconfig`

很多 E_UNEXPECTED 是 `.wslconfig` 配坏了导致的。你现在的位置就是：

```text
C:\Users\12879
```

检查有没有这个文件：

```powershell
notepad $env:USERPROFILE\.wslconfig
```

如果有，先改成最保守配置：

```ini
[wsl2]
networkingMode=NAT
autoProxy=false
```

保存后运行：

```powershell
wsl --shutdown
wsl
```

`.wslconfig` 是 WSL2 的全局配置文件，微软文档写明它放在 `%UserProfile%\.wslconfig`，用于配置 WSL2 虚拟机网络等全局设置。citeturn517462view1

### 4. 如果你确实需要 WSL 使用 Windows 代理

不要在 WSL 里用：

```bash
127.0.0.1:7890
```

NAT 模式下应该用 Windows 主机 IP。等 WSL 能进去后，在 WSL 里查：

```bash
ip route show | grep -i default | awk '{ print $3 }'
```

假设输出是：

```text
172.30.96.1
```

那代理应该写成：

```bash
export http_proxy=http://172.30.96.1:7890
export https_proxy=http://172.30.96.1:7890
```

但你的代理软件要允许 LAN 连接，监听地址最好不是只绑定 `127.0.0.1`。

### 5. 如果还报 E_UNEXPECTED

管理员 PowerShell 里重启 WSL 服务：

```powershell
Restart-Service LxssManager
wsl --shutdown
wsl
```

还不行就执行：

```powershell
wsl --version
wsl --status
wsl -l -v
```

把这三条输出贴出来。重点看：WSL 版本、Windows 版本、你的发行版是不是 Ubuntu，以及 `.wslconfig` 里有没有 `networkingMode=mirrored`。微软文档显示 `networkingMode=mirrored`、`autoProxy` 等属于 WSL2 高级配置，并且 mirrored 需要较新的 Windows 11/WSL 支持；配置不匹配时就容易出这种网络相关启动问题。citeturn517462view1
