我的建议：不要为了“配套 skill”强行新建仓库。你这个“期末试题生成”明显和现有 exam-review-page 是同一套学习/复习工作流，先放在同一个仓库更合理。

Claude Code 识别 skill 主要看文件结构，不是看 GitHub README 里有没有外链。Claude Code 的项目级 skill 路径是：

.claude/skills/<skill-name>/SKILL.md


官方文档也说明，Claude Code 会自动发现项目里的 .claude/skills/<skill-name>/SKILL.md，并且 skill 的命令名通常来自 skill 目录名，比如 .claude/skills/final-exam-generator/SKILL.md 对应 /final-exam-generator。citeturn269000view0

你现在仓库 README 里已经写了 exam-review skill 的说明，但我在仓库文件列表里没看到实际的 .claude/skills/exam-review/SKILL.md 结构，只看到 README、generate_review_page.py、笔记和 HTML/PDF 示例等文件。citeturn303670view0 所以如果你想让别人真的安装/使用 skill，README 说明不够，最好把 skill 文件夹也放进去。

我会这样组织：

exam-review-page/
├── README.md
├── generate_review_page.py
├── examples/
│   └── ...
├── .claude/
│   └── skills/

│           └── SKILL.md


README 里再加一段：

## Claude Code Skills

本仓库包含两个配套 Claude Code skills：

- `/exam-review`：根据教材 PDF 生成交互式复习页面
- `/final-exam-generator`：根据教材、考点笔记、考试范围生成期末模拟题/练习卷

使用方式：
bash
git clone https://github.com/CRF2004/exam-review-page
cd exam-review-page
claude
然后在 Claude Code 中运行：
text
/exam-review ./教材目录
/final-exam-generator ./教材目录 --based-on 复习笔记_考点版.md


什么时候才该新建仓库？

适合放同一个仓库：

你的“期末试题生成”依赖现有的考点笔记格式、PDF 页码引用、复习笔记_考点版.md、甚至未来还想把生成的试题嵌入复习页面。这个就是配套模块，放一起最好。

适合新建仓库：

如果你想把它做成一个完全独立的 skill，比如任何课程 PDF 都能生成试卷，不依赖 exam-review-page，也不关心你现有 HTML 复习页面，那可以新建：

exam-question-generator-skill/
├── README.md
└── final-exam-generator/
    └── SKILL.md


但对你现在这个项目，我建议先别拆。一个仓库里放两个 skill，README 里互相说明关系，是最清晰、维护成本最低的做法。

你可以把定位写成：

> exam-review 负责把资料整理成考点复习页面；
> final-exam-generator 负责基于这些考点生成模拟卷、答案、评分标准和错题回练。

这样比两个仓库互相外链更像一个完整产品。
