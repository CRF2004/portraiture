### 2. 掉落算法（Gravity）

从下往上扫描：

for col in columns:
    write_ptr = bottom
    for row from bottom → top:
        if not empty:
            move to write_ptr
            write_ptr--

### 3. 填充算法（Spawn）

while write_ptr >= 0:
    board[write_ptr][col] = spawn_queue.pop()

### 4. 连锁机制（Cascade Loop）

while True:
    matches = find_matches()
    if not matches:
        break
    eliminate(matches)
    apply_gravity()
    spawn_new()

# 一、为什么你会频繁连锁（本质原因）

### 1. 状态空间太“稠密”

- 4种动物 → 每格随机命中概率 = 1/4
- 连续3个概率 ≈ 1/16（横/纵叠加更高）

再叠加：
- 掉落会“压缩相同元素”
- 补充是随机的

👉 结果：
> 每次消除后，棋盘会进入一个更容易再次匹配的状态

---

### 2. 重力是“匹配放大器”

重力本质做了两件事：

1. 把相同元素压在一起（增加局部密度）
2. 破坏原有结构（引入新组合）


👉 这会显著提高 match probability

---

### 3. 候选池（supply）是纯随机

这点是最大问题：

> 你在“持续往棋盘注入可形成match的随机变量”

---

# 二、你该在哪三层做控制

## ✔ 层1：初始棋盘生成（必须做）

目标：
> 初始状态 无自动消除 + 有可操作空间

### 方法（工业标准）

生成时：

逐格填充：
    随机一个元素
    如果形成3连 → 重选


👉 这一步必须做，否则开局就炸

---

## ✔ 层2：补充策略（关键优化点）

你现在的问题核心就在这里。

### ❌ 错误方式（你现在的）
随机生成 supplyQueue


---

### ✔ 正确思路：“受控随机（controlled randomness）”

## 方法1：局部禁配（推荐）

在补充某个位置时：

检查：
    如果这个元素会立即形成3连 → 禁止


伪代码：

function generateTile(x, y):
    candidates = [0,1,2,3]

    for each type in candidates:
        if 会形成match:
            remove(type)

    return 随机(candidates)


👉 效果：
- 消除“无脑连锁”
- 但保留“可能形成策略性连锁”

# 一、最推荐：引入“阻塞层”（立刻提升难度）

## ✔ 1. 不可移动方块（Blocker）

### 行为
- 不参与消除
- 不随重力移动
- 只能通过“邻近消除”被破坏（或完全不可破坏）

### 两种版本

#### 重度
- 需要2~3次才能消除

---

## ✔ 2. 空洞（Hole）

### 行为
- 该格子永远为空
- 上方方块会“绕过”或停住

### 影响
- 打断重力路径
- 破坏“垂直连锁”

👉 这个非常有效，而且实现很简单（本质是跳过该位置）
